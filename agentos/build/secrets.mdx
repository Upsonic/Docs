---
title: "Secrets"
description: "Give an agent API keys and passwords without putting them in its bundle."
---

Secrets — a CRM API key, a database password — never go into your bundle or `Dockerfile`. You declare their **names** in `agentos.yaml`, an environment admin enters the **values** in the panel, and your code receives them on each invocation in `context.secrets`.

<Steps>
  <Step title="Declare the names">
    ```yaml agentos.yaml
    secrets: [CRM_API_KEY, ERP_PASSWORD]
    ```

    Names match `[A-Z][A-Z0-9_]*` and are at most 128 characters.
  </Step>
  <Step title="Set the values">
    An environment admin opens the agent's **Secrets** tab and enters each value. A value is never shown again after it is saved. Members of the environment see the names, never the values.

    If you deploy a version that declares a name without a value, the deploy warns you: in its log, with a **MISSING SECRETS** badge on the Deploy and Secrets tabs, and in `warnings` on the deploy (`GET /v0/deploys/{id}`).
  </Step>
  <Step title="Read them in your code">
    <CodeGroup>
    ```python Plain HTTP
    crm_key = body["context"]["secrets"]["CRM_API_KEY"]
    ```

    ```python Python SDK
    crm_key = inv.secrets["CRM_API_KEY"]
    ```

    ```ts TypeScript SDK
    const crmKey = inv.secrets.CRM_API_KEY;
    ```
    </CodeGroup>

    `context.secrets` holds the names this version declares that have a value.
  </Step>
</Steps>

## How values are handled

- Values are stored encrypted, decrypted only to build the invoke request, and never written to events, logs or webhooks.
- Secrets are not part of a version. A new value applies from the next invocation on, the resume of a held run included; no redeploy needed.
- The build never gets secrets. Fetch what needs credentials at run time, not in your `Dockerfile`.

## Masking

If your agent echoes a secret of 8 or more characters into its output, its error message, an [event](/agentos/build/files-and-events) or an [ask](/agentos/build/human-approvals) (intent, details, item titles and data), AgentOS stores it as `***`.

This is a safety net, not a guarantee: an encoded or split value isn't recognised, and a value rotated in the middle of an invocation may stay unmasked in that invocation's later events.

<Warning>
Some things are **not** scrubbed. Keep secrets out of them:

- [state](/agentos/build/state-and-sessions) values;
- the input of [child runs](/agentos/build/child-runs) your agent starts;
- a [streamed answer](/agentos/build/streaming), which reaches the caller as written;
- your own logs.
</Warning>
